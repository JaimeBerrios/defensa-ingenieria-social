Instalación

Qué debes descargar

Necesitas Python 3.9 o posterior. VS Code y Git facilitan la edición y el control de versiones. El script prepara Tectonic automáticamente.

Ejecuta los comandos desde la raíz del proyecto.
git --version python --version

La primera compilación requiere conexión. Tectonic se guarda en la carpeta de datos del usuario y se reutiliza entre proyectos.

Git y trabajo en equipo

Descargar la plantilla y comenzar tu proyecto

Una rama te permite trabajar en tu proyecto por separado y conservar la versión base de la plantilla. En los comandos, cambia nombra-tu-rama por un nombre corto para tu trabajo, por ejemplo proyecto-redes. Usa el mismo nombre en todos los pasos.

Primero instala Git. Si estás comenzando, elige HTTPS para descargar. Usa SSH si ya configuraste una clave de acceso en GitHub. Para subir cambios necesitas una cuenta con permiso para modificar este proyecto. Si GitHub te pide identificarte, sigue el inicio de sesión de tu herramienta; la contraseña de tu cuenta no sirve como contraseña de Git.

1. Descargar una copia de la plantilla

Abre la terminal, donde escribirás los comandos. En VS Code está en el menú Terminal → Nueva terminal. Ubícate en la carpeta donde quieras guardar el proyecto y ejecuta solo una de estas dos opciones. Git creará una carpeta llamada Plantilla-Documentos.

Con HTTPS

git clone https://github.com/JaimeBerrios/Plantilla-Documentos.git

Con SSH

git clone git@github.com:JaimeBerrios/Plantilla-Documentos.git

2. Entrar a la carpeta descargada

cd Plantilla-Documentos

3. Comprobar dónde vas a trabajar

El primer comando muestra el nombre de la rama donde estás. Para comenzar desde la plantilla base debe decir main. El segundo muestra si cambiaste algún archivo. Si acabas de descargar la plantilla y aparece otra rama, escribe git switch main. Si ya habías editado archivos, guarda esos cambios con un commit antes de cambiar de rama; el ejemplo del final explica cómo hacerlo.

git branch --show-currentgit status

4. Crear la rama para tu trabajo

Este comando crea la rama y te deja trabajando en ella. Solo una persona del equipo debe crearla. Si un compañero ya la subió a GitHub, ve al apartado “Trabajar con tus compañeros”.

git switch -c nombra-tu-rama

5. Confirmar que estás en tu rama

git branch

El símbolo * debe aparecer junto al nombre de tu rama:

  main
* nombra-tu-rama

6. Subir tu rama a GitHub

git push -u origin nombra-tu-rama

Esto permite que tus compañeros encuentren la rama en GitHub. La opción -u recuerda dónde subir los próximos cambios; después podrás usar simplemente git push.

La plantilla base se conserva. Este comando sube tu rama a GitHub. Tus cambios solo llegarán a main si después alguien decide unirlos a esa rama. Antes de editar o subir archivos, comprueba con git status que estás en la rama de tu proyecto.

Trabajar con tus compañeros

Cuando una persona haya subido la rama, los demás pueden descargarla. Elijan una de estas opciones y usen el nombre de rama que acordó el equipo.

Opción 1 · Descargar la rama del equipo (recomendada)

Con HTTPS

git clone -b nombra-tu-rama --single-branch https://github.com/JaimeBerrios/Plantilla-Documentos.git

Con SSH

git clone -b nombra-tu-rama --single-branch git@github.com:JaimeBerrios/Plantilla-Documentos.git
cd Plantilla-Documentos

Estos comandos te dejan en la rama del equipo, lista para trabajar. La opción --single-branch descarga esa rama con su historial de cambios, sin preparar las demás ramas.

Opción 2 · Descargar la plantilla y luego entrar a la rama del equipo

Con HTTPS

git clone https://github.com/JaimeBerrios/Plantilla-Documentos.git

Con SSH

git clone git@github.com:JaimeBerrios/Plantilla-Documentos.git
cd Plantilla-Documentosgit switch nombra-tu-rama
Opción 3 · Ya tengo la carpeta, pero no encuentro la rama del equipo

Abre la terminal dentro de Plantilla-Documentos. El primer comando consulta las ramas que hay en GitHub. El segundo prepara la rama del equipo en tu computadora y te deja dentro de ella. Sirve tanto con HTTPS como con SSH.

git fetch origingit switch -c nombra-tu-rama --track origin/nombra-tu-rama

Si ya tienes esa rama en tu computadora, basta con git switch nombra-tu-rama. Si descargaste otra rama usando --single-branch, ejecuta primero el siguiente comando y después los dos anteriores:

git remote set-branches --add origin nombra-tu-rama

Comandos para el trabajo diario

Qué hace cada comando en la rama de tu proyecto
ComandoFunción
git statusMuestra en qué rama estás y qué archivos cambiaste.
git diffMuestra lo que agregaste o quitaste en los archivos.
git add .Selecciona los cambios que vas a guardar. Ejecútalo desde Plantilla-Documentos y revisa antes que no incluyas archivos personales.
git diff --cachedMuestra los cambios seleccionados para guardar.
git commit -m "Mensaje"Guarda en tu computadora un punto del historial, llamado commit. Cambia “Mensaje” por una descripción de lo que hiciste.
git pushSube a GitHub los cambios que ya guardaste con commit.
git pull --ff-onlyTrae los cambios de tus compañeros. Se detiene si hay cambios de ambos lados que necesitan revisarse juntos.

Antes de empezar, comprueba que no tienes cambios sin guardar y trae lo que hayan subido tus compañeros:

git statusgit pull --ff-only

Cuando termines de editar, revisa tus cambios, guárdalos con una descripción y súbelos a GitHub. Ejecuta los comandos en este orden:

git diffgit add .git diff --cachedgit commit -m "docs(reporte): actualiza el contenido del proyecto"git push

Si Git no te deja descargar o subir porque un compañero también hizo cambios, revisen juntos el mensaje y acuerden cómo combinarlos. No uses git push --force: podría reemplazar cambios del equipo.

VS Code

Cómo compilar

La carpeta .vscode/ incluye una tarea que ejecuta el mismo compilador y guarda el reporte en pdf/reporte.pdf. La tarea de presentación se elige por separado.

1Completa datos/datos.md y edita los documentos.
2Presiona Ctrl + Shift + B en VS Code.
3Espera la compilación del reporte.
4Revisa los registros en .build/ si aparece un error.
5Abre pdf/reporte.pdf.
python compilar.py python compilar.py --sin-red python compilar.py --con-presentacion

Preparar un trabajo nuevo

Sigue este orden para evitar problemas de rutas, logos, paquetes o archivos sin compilar.

Personalización

Tildes, logos e iconos

Español

Tildes directas

Usa á, é, í, ó, ú, ñ, ¿ y ¡ en documentos/presentacion.tex. Guarda los archivos en UTF-8.

Logos

Portada automática

Conserva los logos de assets/institucional/. Agrega gráficos e imágenes del trabajo en assets/contenido/imagenes/.

Font Awesome

Iconos en LaTeX

Usa comandos como \faUser, \faCloud, \faLightbulb, \faCheckCircle y \faChartLine.

\begin{frame}{\faLightbulb \ Idea principal} \item \textbf{\faCheckCircle \ Punto clave:} descripción breve. \renewcommand{\IconosPortada}{\faCloud \hspace{0.5cm} \faServer}
Font Awesome Free · web

Amplía tu selección de iconos

Descarga SVG oficiales cuando hagan falta. Se guardan con su licencia en assets/iconos/fontawesome/solid/ y siguen funcionando sin conexión.

python -m herramientas.iconos --descargar microscope shield-halved --sincronizar

La sincronización incorpora los iconos a la biblioteca de las diapositivas; después puedes colocarlos junto al texto. Consulta la guía de personalización.

Si los acentos se ven mal, guarda documentos/presentacion.tex como UTF-8 desde la barra inferior de VS Code.

Soporte

Errores comunes

Revisa el mensaje del compilador y los registros de .build/. Si falla un documento, se conservan los PDF anteriores.

python no se reconoce

Instala Python 3.9 o posterior, habilita su acceso desde la terminal y vuelve a abrir VS Code.

Falta un paquete

Ejecuta python compilar.py con conexión para que Tectonic descargue los paquetes necesarios.

Falta un dato obligatorio

Completa el campo indicado en datos/datos.md y conserva sus encabezados y etiquetas.

La primera compilación no tiene conexión

Conéctate para descargar Tectonic y sus paquetes. Usa --sin-red cuando ya estén disponibles.

No aparece el PDF actualizado

Confirma que python compilar.py terminó correctamente. Ante un fallo, los PDF anteriores siguen en pdf/.
